# 02. Роли и права

## 1. Роли
| Роль | Код | Кто это |
|---|---|---|
| Администратор системы | `admin` | Настраивает систему: пользователи, роли, воронки, шаблоны, интеграции. Обычно совмещается с руководителем |
| Руководитель | `director` | Владелец бизнеса. Видит всё, включая деньги и маржу, распределяет заказы |
| Менеджер | `manager` | Ведёт заявки, клиентов и заказы, считает сметы, общается с клиентами |
| Мастер | `master` | Выполняет диагностику, ремонт, сборку, испытания, выезды |
| Бухгалтер / офис-администратор | `accountant` | Счета, оплаты, документы, склад и закупки, обмен с 1С |

- **ПРВ-1** (Э0, обязательно). У пользователя может быть несколько ролей. Права складываются (берётся максимальное).
- **ПРВ-2** (Э0, обязательно). Роли и их права хранятся в БД. В MVP набор ролей фиксированный (5 ролей выше), права ролей можно менять галочками в настройках. Создание новых ролей — Э3, желательно.
- **ПРВ-3** (Э0, обязательно). Пользователя нельзя удалить, только деактивировать. Деактивированный не может войти, но остаётся автором записей и ответственным в старых заказах.
- **ПРВ-4** (Э1, обязательно). При деактивации пользователя система показывает его открытые заказы, заявки и задачи и предлагает передать их другому сотруднику.

## 2. Уровни доступа
| Обозначение | Значение |
|---|---|
| **П** | Полный доступ: просмотр, создание, изменение, архивирование |
| **И** | Просмотр всего + изменение |
| **Ч** | Только просмотр |
| **С** | Только своё: где пользователь ответственный, исполнитель или участник |
| **—** | Нет доступа, раздел скрыт |

Примечания:
1. Если руководитель включил настройку «Менеджер видит только своих клиентов» — только свои (где он ответственный). По умолчанию выключено: менеджер видит всех.
2. Мастер видит только клиентов своих заказов, и только имя, контакт и оборудование. Реквизиты и финансы скрыты.
3. Мастер может менять этап только на производственных этапах своего заказа: диагностика, ремонт, сборка, испытания, работы на выезде (см. [Заказы](04-модули/03-заказы.md)).
4. Бухгалтер может перевести заказ в «Выдан / оплачен» и отметить оплату.
5. Мастер видит список работ и запчастей, но без цен и сумм. Может добавлять предложения по позициям при диагностике, менеджер их утверждает.
6. Менеджер видит маржу по своим заказам, если это включено настройкой «Показывать менеджерам маржу». По умолчанию выключено.
7. Свои задачи (поставленные себе или им) — полный доступ. Чужие задачи — только по своим заказам.
8. Мастер формирует акт приёмки, дефектную ведомость и протокол испытаний по своим заказам.
9. Менеджер видит воронку и конверсию только по своим заявкам и заказам.
10. Бухгалтер видит статус и ошибки обмена с 1С и может запустить повторную синхронизацию.

## 4. Правила проверки
- **ПРВ-10** (Э0, обязательно). Права проверяются на сервере на уровне эндпоинта (guard по действию) и на уровне записи (фильтр «только своё»).
- **ПРВ-11** (Э1, обязательно). Скрытые поля (себестоимость, маржа, цены для мастера) не передаются в ответе API, а не просто скрываются в интерфейсе.
- **ПРВ-12** (Э1, обязательно). Попытка доступа без прав возвращает 403 и пишется в журнал.
- **ПРВ-13** (Э1, обязательно). Права описаны в `packages/shared` как константы `Permission` (например, `orders.view`, `orders.changeStage`, `orders.viewMargin`) и используются и сервером, и интерфейсом.
- **ПРВ-14** (Э1, обязательно). На каждое правило матрицы есть API-тест: роль с доступом получает 200, без доступа 403.

## 5. Настройки видимости (уровень компании)
| Настройка | По умолчанию |
|---|---|
| Менеджер видит только своих клиентов и заказы | Выключено |
| Показывать менеджерам маржу по своим заказам | Выключено |
| Лимит скидки без согласования руководителя | 10% |
| Мастер видит цены в смете | Выключено |
