# Модуль 01. Клиенты

Единая база клиентов, их контактных лиц и оборудования. Связанные сущности: `Client`, `Contact`, `Equipment` ([Модель данных](../03-модель-данных.md#4-клиенты)).

## Экраны
1. **Список клиентов** — таблица с поиском и фильтрами.
2. **Карточка клиента** — шапка и вкладки.
3. **Карточка оборудования** — параметры станции и история ремонтов.
4. **Форма клиента** — создание и редактирование.

## Требования

### Список
- **КЛН-1** (Э1, обязательно). Таблица: название/ФИО, тип, телефон, ответственный менеджер, число заказов, сумма заказов за всё время, долг, дата последнего заказа, метки.
- **КЛН-2** (Э1, обязательно). Поиск по одной строке: название, ФИО, телефон (в любом формате: `8 912…`, `+7 912…`, `912…`), почта, ИНН, серийный номер оборудования. Результат за 300 мс.
- **КЛН-3** (Э1, обязательно). Фильтры: тип, менеджер, метки, источник, «есть долг», «есть открытые заказы», «без заказов больше N месяцев».
- **КЛН-4** (Э3, желательно). Выгрузка списка в Excel (с учётом фильтров и прав).

### Карточка клиента
- **КЛН-10** (Э1, обязательно). Шапка: название, тип, телефон и почта (клик по телефону — звонок `tel:`, с Э4 — через телефонию), ответственный, метки, долг, кнопки «Новый заказ», «Новая задача», «Написать».
- **КЛН-11** (Э1, обязательно). Вкладки:
  - **Обзор** — реквизиты, адрес, условия оплаты, каналы уведомлений, заметка;
  - **Контакты** — контактные лица;
  - **Оборудование** — станции клиента;
  - **Заказы** — все заказы с этапом, суммой, оплатой;
  - **Заявки**;
  - **История** — единая лента событий: заказы, звонки, письма и сообщения, документы, оплаты, задачи (по дате, с фильтром по типу);
  - **Переписка** (Э4) — см. [Общение](05-общение.md);
  - **Документы** — все документы клиента;
  - **Журнал** — журнал изменений (только руководитель).
- **КЛН-12** (Э2, обязательно). Финансовый блок: всего заказов на сумму, оплачено, долг, просроченный долг. Скрыт для мастера.

### Создание и редактирование
- **КЛН-20** (Э1, обязательно). Обязательные поля: тип и название (ФИО). Должен быть хотя бы один телефон или почта.
- **КЛН-21** (Э1, обязательно). Для ИП, юрлиц и дилеров поле ИНН с проверкой контрольной суммы.
- **КЛН-22** (Э2, желательно). Автозаполнение реквизитов по ИНН через API DaData (бесплатный тариф).
- **КЛН-23** (Э1, обязательно). Телефоны нормализуются в E.164 при сохранении.
- **КЛН-24** (Э1, обязательно). При вводе телефона, почты или ИНН система ищет совпадения и предупреждает: «Похоже, клиент уже есть: …» с кнопкой «Открыть». Сохранить дубль можно, но с подтверждением.
- **КЛН-25** (Э1, обязательно). Для физлиц — отметка «Согласие на обработку ПД получено» (см. АРХ-21).

### Дубли
- **КЛН-30** (Э3, желательно). Объединение двух карточек: выбирается основная, из второй переносятся контакты, оборудование, заказы, заявки, сообщения, звонки, документы. Вторая архивируется. Действие пишется в журнал. Только руководитель и администратор.

### Оборудование
- **КЛН-40** (Э1, обязательно). У клиента может быть несколько станций. Поля — см. модель `Equipment`.
- **КЛН-41** (Э1, обязательно). Карточка станции показывает историю всех заказов по ней: дата, что делали, какие запчасти меняли, гарантия, сумма.
- **КЛН-42** (Э1, обязательно). При создании заказа на ремонт можно выбрать станцию клиента или создать новую прямо в форме заказа.
- **КЛН-43** (Э1, обязательно). Поиск станции по серийному номеру из глобального поиска.
- **КЛН-44** (Э2, желательно). Фото шильдика и паспорта станции во вложениях.

### Дилеры и цены
- **КЛН-50** (Э2, обязательно). Для клиента можно указать прайс-лист или общую скидку. При добавлении позиций в смету цены берутся из прайс-листа клиента.
- **КЛН-51** (Э2, обязательно). Условия оплаты: предоплата или отсрочка N дней. От этого зависит срок оплаты в счёте и расчёт просроченного долга.

### Удаление и архив
- **КЛН-60** (Э1, обязательно). Клиента без заказов можно удалить (мягко). Клиента с заказами — только архивировать. Архивные скрыты из списка по умолчанию, но ищутся.

## Критерии приёмки
- Менеджер находит клиента по последним 4 цифрам телефона или по серийному номеру станции.
- При заведении клиента с уже существующим телефоном система показывает предупреждение.
- Мастер, открыв клиента своего заказа, не видит реквизиты и финансы. В ответе API этих полей нет.
- В истории клиента видны все его заказы, документы и оплаты в хронологическом порядке.
