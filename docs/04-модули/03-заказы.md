# Модуль 03. Заказы

Центральный модуль системы. Принцип: **у каждого заказа одна карточка**, и в ней всё — этап, люди, смета, запчасти, обсуждение, документы, деньги. Сущности: `Order`, `Pipeline`, `Stage`, `OrderItem`, `OrderStageHistory`, `OrderApproval` ([Модель данных](../03-модель-данных.md#6-заказы)).

## 1. Типы заказов и воронки
Этапы по умолчанию создаются seed-скриптом. Названия, порядок, нормы и уведомления можно менять в настройках, системные коды (`code`) — нет, на них завязаны правила.

## 2. Правила переходов между этапами
- **ЗАК-1** (Э1, обязательно). Переход вперёд на любой этап разрешён по умолчанию. Назад — тоже, но с обязательным комментарием.
- **ЗАК-2** (Э1, обязательно). Мастер может переводить заказ только между производственными этапами и на этап, следующий за производственным (например, из `testing` в `ready`).
- **ЗАК-3** (Э1–Э2, обязательно). Проверки при входе в этап (блокируют переход, показывают, чего не хватает):

| Этап | Условие | Этап ТЗ |
|---|---|---|
| `accepted` | Указано оборудование, загружено хотя бы одно фото | Э1 |
| `estimate` | В смете есть хотя бы одна утверждённая позиция | Э1 |
| `awaiting_parts`, `repair` | Смета согласована (есть запись `OrderApproval`) | Э1 |
| `repair`, `assembly` | Назначен хотя бы один мастер | Э1 |
| `ready` (ремонт, сборки) | Заполнен протокол испытаний, все параметры в норме или есть комментарий руководителя | Э2 |
| `ready` | Все запчасти из сметы списаны или сняты с резерва | Э2 |
| `done` | Заказ оплачен полностью, или у клиента есть отсрочка и выставлен счёт | Э2 |
| `cancelled` | Указана причина отказа | Э1 |
| `procurement` (сборка под заказ) | Есть оплата по счёту на предоплату (или руководитель отметил «без предоплаты») | Э2 |

- **ЗАК-4** (Э1, обязательно). Руководитель может пропустить проверку с обязательным комментарием («Выдать без оплаты: договорились, оплатят в пятницу»). Факт обхода пишется в журнал и в ленту.
- **ЗАК-5** (Э1, обязательно). Каждая смена этапа пишется в `order_stage_history` и в ленту заказа как системное событие.
- **ЗАК-6** (Э2, обязательно). При входе в этап с `client_notify = true` ставится задача отправки уведомления клиенту (см. [Уведомления клиенту](09-уведомления-клиенту.md)).
- **ЗАК-7** (Э1, обязательно). Если заказ находится на этапе дольше `norm_hours`, он помечается «Без движения», ответственный получает уведомление, заказ попадает в список руководителя «Застрявшие заказы».

## 3. Экраны
1. **Канбан** — колонки по этапам выбранной воронки, перетаскивание карточек меняет этап (с проверками ЗАК-3).
2. **Таблица заказов** — все типы в одном списке.
3. **Карточка заказа**.
4. **Мои заказы** — для мастера: заказы, где он исполнитель, сгруппированные по этапу.

## 4. Требования

### Списки
- **ЗАК-10** (Э1, обязательно). Канбан: переключатель воронки (4 типа), карточка показывает номер, клиента, оборудование, ответственного, исполнителей, плановую дату, сумму (по правам), значки «Просрочен», «Без движения», «Срочно», число непрочитанных комментариев.
- **ЗАК-11** (Э1, обязательно). Таблица: номер, тип, этап, клиент, оборудование, менеджер, мастера, создан, плановая дата, сумма, оплачено, долг. Фильтры: тип, этап, менеджер, мастер, клиент, период, «просрочен», «без движения», «не оплачен». Сортировка по любому столбцу.
- **ЗАК-12** (Э1, обязательно). Канбан и таблица обновляются в реальном времени (WebSocket), когда коллега меняет заказ.
- **ЗАК-13** (Э1, обязательно). Сохранённые фильтры («Мои просроченные», «Готовы к выдаче»).

### Создание
- **ЗАК-20** (Э1, обязательно). Создание из заявки, из карточки клиента или с нуля. Обязательные поля: тип, клиент, краткое описание. Для ремонта — оборудование (можно создать на лету). Для сборки типовой — модель из номенклатуры.
- **ЗАК-21** (Э1, обязательно). Плановая дата готовности по умолчанию = сегодня + сумма норм этапов воронки (можно изменить).
- **ЗАК-22** (Э1, обязательно). Гарантийный случай: при создании ремонта по станции, у которой действует гарантия, система предлагает отметить «Гарантийный» и связать с исходным заказом. Гарантийные позиции по умолчанию с ценой 0.
- **ЗАК-23** (Э2, обязательно). При создании сборки типовой станции смета заполняется по составу модели (`product_bom`) + работы сборки из шаблона.

### Карточка заказа
- **ЗАК-30** (Э1, обязательно). Шапка: номер, тип, этап (с выпадающим списком перехода), клиент (ссылка), оборудование, менеджер, исполнители, приоритет, плановая дата, индикаторы оплаты. Кнопки: «Следующий этап», «Документ», «Задача», «Уведомить клиента», «Ссылка на статус».
- **ЗАК-31** (Э1, обязательно). Полоса этапов (прогресс) с датами прохождения.
- **ЗАК-32** (Э1, обязательно). Вкладки:
  - **Лента** — комментарии, фото и системные события (по умолчанию открыта);
  - **Смета** — позиции;
  - **Диагностика** — дефектная ведомость (Э2);
  - **Испытания** — протокол (Э2);
  - **Запчасти** — резервы и списания (Э2);
  - **Выезды** — для выездного ремонта;
  - **Документы** (Э2);
  - **Оплаты** (Э2);
  - **Задачи**;
  - **История** — этапы и журнал изменений.
- **ЗАК-33** (Э1, обязательно). Загрузка фото со смартфона прямо с камеры в ленту или в карточку (приёмка, дефекты, результат). Сжатие на клиенте до 2560 px по длинной стороне.

### Смета
- **ЗАК-40** (Э1, обязательно). Позиции трёх видов: работа, запчасть, услуга (выезд, доставка). Запчасть выбирается из номенклатуры (с Э2, до этого — свободный ввод), работа — из прайса работ или свободным вводом.
- **ЗАК-41** (Э1, обязательно). Для каждой строки: количество, единица, цена, скидка, сумма. Себестоимость и маржа — только для ролей с правом `orders.viewMargin`.
- **ЗАК-42** (Э1, обязательно). Итог: сумма работ, сумма запчастей, скидка, НДС (по настройке компании), итого. Маржа заказа в рублях и процентах (по правам).
- **ЗАК-43** (Э1, обязательно). Мастер на диагностике добавляет позиции со статусом «Предложено» (без цен). Менеджер видит их выделенными, проставляет цены и утверждает.
- **ЗАК-44** (Э1, обязательно). Согласование сметы: кнопка «Смета согласована» с выбором способа (телефон, почта, Telegram, подписанный документ, кнопка на странице статуса — Э2) и именем согласовавшего. Создаётся запись `OrderApproval` с версией и суммой.
- **ЗАК-45** (Э1, обязательно). Изменение утверждённых позиций после согласования помечает их как «Доп. работы» (`is_extra`) и требует повторного согласования на сумму разницы. Заказ не переходит на `ready`, пока доп. работы не согласованы или не отклонены.
- **ЗАК-46** (Э1, обязательно). Скидка выше лимита (настройка, по умолчанию 10%) требует подтверждения руководителя: создаётся задача руководителю, до подтверждения смету нельзя отправить клиенту.
- **ЗАК-47** (Э2, обязательно). Из сметы формируются документы: смета, КП, счёт.
- **ЗАК-48** (Э2, желательно). Шаблоны смет: сохранить набор позиций как шаблон («Ремонт НШ-32 типовой») и подставлять в новые заказы.

### Ответственные и исполнители
- **ЗАК-50** (Э1, обязательно). Менеджер — один на заказ. Исполнителей-мастеров может быть несколько, один отмечается главным.
- **ЗАК-51** (Э1, обязательно). При назначении исполнителя ему приходит уведомление.
- **ЗАК-52** (Э2, желательно). Учёт трудозатрат: мастер отмечает часы по заказу (кнопка «Начать/закончить работу» или ввод вручную). Используется в отчёте загрузки и для фактической себестоимости работ.

### Публичная ссылка на статус
- **ЗАК-60** (Э2, обязательно). У каждого заказа есть ссылка `https://<домен>/s/<status_token>`. Подробности — в [Уведомлениях клиенту](09-уведомления-клиенту.md).

### Гарантия
- **ЗАК-70** (Э2, обязательно). На этапе `done` для ремонтов и сборок создаётся запись гарантии: срок по умолчанию из настроек (например, 6 месяцев на ремонт, 12 на сборку), можно изменить в заказе.
- **ЗАК-71** (Э2, желательно). За 14 дней до окончания гарантии менеджеру создаётся задача «Предложить ТО», клиенту (по настройке) уходит напоминание.

## 5. Критерии приёмки
- Заказ на ремонт проходит все 10 этапов, и на каждом проверке ЗАК-3 срабатывают правильно.
- Мастер со смартфона переводит свой заказ из «Диагностики» в «Смету», добавив предложенные позиции и фото. Цены и маржу он не видит.
- Попытка выдать заказ без оплаты блокируется. Руководитель может обойти блокировку с комментарием, и это видно в ленте и журнале.
- Заказ, простоявший на этапе дольше нормы, появляется в «Застрявших» у руководителя.
- Два пользователя видят перемещение карточки в канбане друг у друга без перезагрузки страницы.
