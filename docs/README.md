## Сводка решений
| Вопрос | Решение |
|---|---|
| Кто разрабатывает | Владелец бизнеса вместе с Claude |
| Стек | TypeScript: NestJS + React + PostgreSQL |
| Где работает | Облачный VPS у российского хостинга |
| 1С | 1С:Бухгалтерия предприятия, установлена на ПК в офисе |
| Телефония | Пока нет, подбираем к этапу 4 (рекомендуем Novofon или Mango Office) |
| Уведомления клиенту | Telegram-бот, почта, SMS, страница статуса заказа |
| Шаблоны документов | Составляем с нуля |
| Масштаб | 6–20 пользователей, 15–20 заказов в месяц, около 20 складских позиций |
| Запуск | Поэтапно, MVP за 2–3 месяца |

## Глоссарий
| Термин | Значение |
|---|---|
| **Заявка** | Первичное обращение клиента из любого канала. Ещё не заказ: может быть отклонена или превращена в заказ |
| **Заказ** | Работа для клиента: ремонт в цеху, выездной ремонт, сборка под заказ или сборка типовой станции |
| **Воронка** | Набор этапов для одного типа заказа |
| **Этап** | Шаг воронки (например, «Диагностика»). У заказа в каждый момент ровно один текущий этап |
| **Выезд** | Поездка мастера к клиенту в рамках выездного ремонта |
| **Оборудование клиента** | Конкретная гидростанция клиента с серийным номером, по которой ведётся история ремонтов |
| **Номенклатура** | Справочник товаров склада: запчасти, комплектующие, типовые станции |
| **Позиция заказа** | Строка сметы: работа или запчасть с количеством, себестоимостью и ценой |
| **Резерв** | Запчасть на складе, закреплённая за заказом, но ещё не списанная |
| **Лента заказа** | Комментарии, фото, файлы и системные события внутри карточки заказа |
| **Компания** | Организация-владелец данных. Сейчас одна, в будущем систему смогут использовать несколько компаний |
| **MVP** | Первая рабочая версия (этап 1) |

## Как работать с ТЗ
- Каждое требование имеет код вида `ЗАК-12` (префикс модуля + номер). На код ссылаются задачи, коммиты и тесты.
- Префиксы: `АРХ` архитектура, `ПРВ` права, `КЛН` клиенты, `ЗАЯ` заявки, `ЗАК` заказы, `ВЫЕ` выезды, `ОБЩ` общение, `ЗАД` задачи и уведомления, `СКЛ` склад, `ДОК` документы, `УВК` уведомления клиенту, `АНЛ` аналитика, `ИНТ` интеграции, `API` API, `ИНФ` интерфейс.
- У каждого требования указан этап (`Э1`–`Э4`), на котором оно делается.
- Если требование меняется, правим ТЗ в том же коммите, что и код.
- Метки важности: **обязательно** — без этого этап не принимается; **желательно** — делаем, если хватает времени, иначе переносим.
