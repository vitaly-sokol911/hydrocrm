# Проверка безопасности ГидроCRM

Дата проверки: 13.10.2026. Проверялись серверная часть (NestJS), интерфейс (React) и сборка для GitHub Pages.

## Две версии — разные риски
| Версия | Где работает | Что защищаем |
|---|---|---|
| **Рабочая** (`apps/api` + `apps/web`) | Свой сервер с PostgreSQL | Данные клиентов и компании, доступ сотрудников |
| **Версия без сервера** (`pnpm build:demo`) | GitHub Pages | Сервера и базы нет, данные вымышленные и живут только в браузере посетителя. Защищаем страницу от вставки чужого кода и репозиторий от утечки секретов |

## Найдено и исправлено
| № | Проблема | Риск | Исправление |
|---|---|---|---|
| 1 | **Чужие идентификаторы в запросах.** В заказ можно было передать контакт, оборудование, мастера или родительский заказ другой компании, в заявку — чужого клиента, в задачу — чужой заказ, в выезд — чужих мастеров, в файл — чужой выезд | Утечка данных между компаниями (когда систему начнут продавать другим) | Проверки принадлежности `apps/api/src/common/ownership.ts` во всех сервисах, принимающих такие идентификаторы |
| 2 | **Тип файла проверялся только по заявлению браузера** | Под видом картинки можно загрузить HTML и открыть его по ссылке CRM | Проверка «магических байтов» для картинок и PDF; всё остальное отдаётся только на скачивание (`Content-Disposition: attachment`) и с `X-Content-Type-Options: nosniff` |
| 3 | **Не было ограничения частоты запросов** (требование АРХ-17) | Подбор паролей, перегрузка сервера | `@nestjs/throttler`: 120 запросов в минуту с IP, вход — 10 в минуту, обновление сессии — 30. Вместе с блокировкой аккаунта после 5 ошибок |
| 4 | **Не было защитных заголовков** | Встраивание в чужой сайт (кликджекинг), загрузка чужих скриптов | `helmet` с CSP: скрипты только свои, запрет встраивания во фреймы, строгая политика referrer |
| 5 | **У сборки для GitHub Pages не было CSP** | На GitHub Pages нельзя задать заголовки | CSP добавляется в страницу meta-тегом при сборке (`vite.config.ts`) |
| 6 | **Уязвимости react-router 6** (открытое перенаправление через `\` в ссылке) | Низкий — все переходы внутренние, но исправление бесплатно | Обновление до react-router 7 |
| 7 | Превышение лимита отдавалось с кодом «конфликт» | Путаница в интерфейсе | Отдельный код `RATE_LIMITED` |

## Проверено, проблем нет
- **Пароли** — argon2id, минимум 8 символов, блокировка после 5 неудачных попыток на 15 минут, одинаковый ответ «неверный email или пароль».
- **Сессии** — access-токен на 15 минут в памяти вкладки (не в localStorage), refresh-токен в httpOnly + SameSite=Strict + Secure cookie на узком пути, ротация при каждом обновлении, повторное использование старого токена отзывает все сессии пользователя.
- **Права** — проверяются на сервере на каждом эндпоинте; скрытые поля (цены и маржа для мастера, реквизиты) не попадают в ответ, а не прячутся в интерфейсе.
- **Изоляция компаний** — фильтр `companyId` добавляется автоматически во все запросы к корневым таблицам (`tenant.extension.ts`), WebSocket проверяет компанию при подписке на комнату.
- **SQL-инъекции** — запросы только через Prisma; два «сырых» запроса используют параметризованные шаблоны.
- **XSS** — React экранирует вывод, нет `dangerouslySetInnerHTML` и `eval`; ссылка на разработчика принимается только с `https://`.
- **Входные данные** — все тела запросов проверяются Zod-схемами, лишние поля отбрасываются (нет «массового присваивания»).
- **Ошибки** — пользователю уходит только понятный текст и код, без стека и деталей БД.
- **Файлы** — ссылки на скачивание подписаны HMAC и живут 1 час, лимит 20 МБ, SVG и HTML запрещены.
- **Режим витрины** — вход по ролям работает только при `DEMO_MODE=true`; в приложении нельзя менять пароли, создавать пользователей и назначать администраторов.
- **Секреты** — `.env` не попадает в git, в репозитории только `.env.example` без настоящих значений; в продакшене сервер не запустится со слабым `JWT_SECRET`.
- **Снимок данных примера** — без паролей, токенов и журнала действий; все люди и компании вымышлены.

## Осознанно оставленные риски
| Риск | Почему не критично | Когда вернуться |
|---|---|---|
| `deepmerge-ts` в Prisma CLI (переполнение стека) | Используется только при сборке на компьютере разработчика для чтения локального конфига, к данным пользователей не относится | При переходе на Prisma 8 |
| Сообщение «аккаунт заблокирован» показывает, что такой email существует | Появляется только после 5 неудачных попыток, при лимите 10 попыток в минуту с IP | При выходе в продажу другим компаниям |
| Лимиты запросов хранятся в памяти процесса | При одном сервере это корректно | При запуске нескольких экземпляров API — перенести в Redis |
| Журнал просмотров карточек клиентов (АРХ-22) | Журнал изменений ведётся, просмотры — ещё нет | Этап 2 |
